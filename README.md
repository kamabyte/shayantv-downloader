# shayantv-downloader

Зеркалирует все мультфильмы с <https://shayantv.ru/cartoons/> в медиатеку, готовую для Jellyfin,
и поддерживает её в актуальном состоянии: каждый запуск по расписанию скачивает только новые серии.

> **Дисклеймер.** Это неофициальный инструмент, он никак не связан с телеканалом «Шаян ТВ».
> Все мультфильмы принадлежат их правообладателям. Используйте его только для личного просмотра
> того, что сайт и так открыто показывает, и не распространяйте скачанное. Пожалуйста, не ставьте
> большой `CONCURRENCY`: не стоит нагружать чужой сайт.

## Что получится

```
Лунтик и его друзья/
├── tvshow.nfo            # название, студия, жанры; заблокировано, чтобы Jellyfin не перезаписывал
├── poster.jpg            # 1000×1500, собирается из горизонтальной картинки с сайта
├── fanart.jpg            # картинка с сайта как фон
├── landscape.jpg         # картинка с сайта как миниатюра
└── Season 01/
    ├── Лунтик и его друзья - S01E01 - 1 серия.mkv
    ├── Лунтик и его друзья - S01E01 - 1 серия.nfo
    └── Лунтик и его друзья - S01E01 - 1 серия-thumb.jpg
```

- **Видео:** лучший вариант из HLS (почти везде 1080p H.264), без перекодирования — поток
  перепаковывается в MKV без потерь.
- **Звук и субтитры:** берутся все дорожки из HLS master. Сейчас у каждой серии одна звуковая
  дорожка и нет субтитров. CDN помечает татарскую озвучку как `en`, поэтому теги переназначаются
  (`en→tat`, `ru→rus`) через `LANGUAGE_MAP`.
- **Объём:** весь каталог (~745 серий, ~106 ч) занимает примерно **240 ГБ**.

## Как это работает

1. Со страницы `/cartoons/` собираются карточки сериалов (название, slug, картинка).
2. На странице каждого сериала есть JSON `JSAppData` с сезонами, сериями и HLS-ссылками.
3. Серия опознаётся по хешу в её HLS-ссылке. Номер сезона и серии присваивается **один раз**
   и сохраняется в `data/state.sqlite3`, поэтому последующие изменения на сайте не переименуют
   уже скачанные файлы.
   - В номерах на сайте бывают ошибки (например, у «Смешариков» две «серии 1», вторая называется
     «2 серия»). Приоритет у номера из названия, затем у номера с сайта. Настоящие совпадения
     дописываются после последней серии сезона.
   - Записи, которые ведут на один и тот же поток (например, «Фиксики» 12 и 13), скачиваются один раз.
4. Скачивание идёт в `*.mkv.part`, файл проверяется через ffprobe (потоки на месте, длительность
   совпадает с указанной на сайте) и только потом переименовывается в `.mkv`. Неудавшаяся серия
   повторяется при следующем запуске.

## Запуск через Docker Compose

Образ собирается GitHub Actions при каждом push в `main` и публикуется как
`ghcr.io/kamabyte/shayantv-downloader:{latest, sha-<коммит>}` (только `linux/amd64`).

1. Подготовьте каталоги. Контейнер их **не создаёт** (`create_host_path: false`): если диск
   не примонтирован, контейнер просто не запустится, а не начнёт заполнять системный диск.
   ```sh
   sudo install -d -o 1000 -g 1000 /srv/shayantv/data "/srv/media/Shayan TV"
   ```
2. Скопируйте [`compose.yml`](compose.yml) и [`.env.example`](.env.example) → `.env`, поправьте
   пути, `PUID`/`PGID` (владелец каталогов) и остальное.
3. `docker compose up -d`

В Dokploy или Portainer то же самое: стек типа Compose, вставьте `compose.yml`, а переменные
из `.env.example` — на вкладку Environment.

### Обновление и откат

```sh
docker compose pull && docker compose up -d   # latest
IMAGE_TAG=sha-1a2b3c4 docker compose up -d    # закрепить конкретный коммит
```

При перезапуске серии, которые уже качаются, получают до 2 минут на завершение
(`stop_grace_period`). Остальные из очереди докачаются в новом контейнере.

### Деплой в Dokploy одной командой

[`deploy/deploy.sh`](deploy/deploy.sh) ждёт сборку образа для коммита в Actions, копирует
`compose.yml` из этого коммита в Raw-стек Dokploy, выставляет `IMAGE_TAG=sha-<коммит>` и запускает
Deploy. Тег всегда конкретный, а не `latest`: compose не скачивает заново тег, который уже есть на хосте.

```sh
echo 'DOKPLOY_URL=http://dokploy.example.lan' > deploy/deploy.env   # один раз, файл в .gitignore
security add-generic-password -U -a "$USER" -s dokploy-api -w      # один раз, API-ключ Dokploy
deploy/deploy.sh             # задеплоить origin/main
deploy/deploy.sh <commit>    # откатиться / закрепить конкретный коммит
```

Имена проекта и стека задаются через `PROJECT` и `STACK` (по умолчанию `shayantv-downloader`
и `downloader`). Нужны `gh`, `jq` и `curl`.

## Эксплуатация

```sh
docker compose ps                                              # статус (healthy/unhealthy)
docker compose logs -f --tail 50
docker compose exec downloader shayantv-dl status              # прогресс по сериалам
docker compose exec downloader shayantv-dl run --dry-run       # что скачается при следующем запуске
```

`run` и демон используют общий lock-файл, поэтому ручной запуск не пересечётся с плановым.

**Healthcheck** (`shayantv-dl health`): контейнер становится unhealthy, если прогресса не было 2 часа
или последняя синхронизация сломалась целиком (изменилась вёрстка сайта или упали все загрузки).
Отдельные неудачные серии повторяются при следующей синхронизации и не считаются.

Если каталог состояния потерян, следующая синхронизация заново обойдёт сайт и пропустит уже
существующие файлы — повторно ничего не скачается.

## Настройки (переменные окружения)

| Переменная          | По умолчанию       | Что делает                                                  |
|---------------------|--------------------|-------------------------------------------------------------|
| `DATA_PATH`         | –                  | Каталог состояния на хосте (только compose, обязательно)    |
| `MEDIA_PATH`        | –                  | Каталог медиатеки на хосте (только compose, обязательно)    |
| `PUID` / `PGID`     | `1000` / `1000`    | Пользователь и группа процесса (только compose)             |
| `IMAGE_TAG`         | `latest`           | Тег образа (только compose)                                 |
| `TZ`                | `Europe/Moscow`    | Часовой пояс для логов                                      |
| `INTERVAL_HOURS`    | `12`               | Интервал между синхронизациями                              |
| `CONCURRENCY`       | `2`                | Сколько серий качать параллельно                            |
| `DOWNLOAD_ATTEMPTS` | `3`                | Повторы одной серии в рамках одного запуска                 |
| `LANGUAGE_MAP`      | `en=tat,ru=rus`    | Тег языка из HLS → тег ISO 639-2, который пишется в MKV     |
| `DEFAULT_LANGUAGE`  | `tat`              | Тег для неизвестного или отсутствующего языка               |
| `JELLYFIN_URL`      | –                  | Например, `http://jellyfin:8096`; включает автосканирование |
| `JELLYFIN_API_KEY`  | –                  | Jellyfin → Dashboard → API Keys                             |
| `LIBRARY_DIR`       | `/library`         | Корень медиатеки внутри контейнера                          |
| `STATE_DIR`         | `/data`            | Каталог состояния внутри контейнера                         |

## Медиатека в Jellyfin

Добавьте **отдельную** медиатеку, например «Шаян ТВ», тип содержимого **Shows** (сериалы),
папка — та, что смонтирована как `MEDIA_PATH`. Затем:

- **Metadata downloaders / Image fetchers:** снимите все галочки (TheMovieDb и т. д.).
  Все метаданные берутся из локальных NFO и картинок.
- **Metadata readers:** оставьте включённым **Nfo**.
- **Preferred metadata language:** Russian.

Infuse тоже подхватывает локальные `.nfo`, `poster.jpg` и `fanart.jpg`, если включить локальные
метаданные для общей папки.

## Разработка

```sh
uv sync
uv run pytest
LIBRARY_DIR=./library STATE_DIR=./data uv run shayantv-dl run --only shayan-yashelchalar
```

Без Docker нужны `ffmpeg` и `ffprobe` в `PATH`.
